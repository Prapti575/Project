# NetShield — Network Intrusion Detection System

NetShield is a Python-based, rule-driven Network Intrusion Detection System (NIDS) developed as an educational cybersecurity project for the BharatCares | IBM SkillsBuild Cybersecurity Bootcamp. It analyzes network-flow records supplied through CSV files and identifies potentially suspicious traffic patterns using predefined security rules.

## Overview

Network traffic contains useful information about communication between devices. Unusual patterns, such as a source contacting many destination ports, an excessive number of flows, or an unexpectedly large data transfer, may indicate activity that requires investigation.

NetShield provides a simple interactive dashboard for analyzing structured network traffic records. It applies predefined rules, generates alerts for matching patterns, and presents the results in a readable format.

The application is designed for learning and demonstration. It does not use machine learning and does not independently capture live network packets.

## Objectives

- Analyze network traffic records provided in CSV format.
- Identify potential port-scanning activity.
- Detect unusually high network-flow counts associated with a source IP address.
- Flag individual flows with unusually large byte counts.
- Display detection explanations and severity information.
- Present traffic analysis results through an interactive dashboard.
- Support visual exploration and CSV export where implemented.
- Demonstrate fundamental network monitoring and cybersecurity concepts.

## Features

- **CSV Traffic Analysis:** Load compatible network-flow records for analysis.
- **Rule-Based Detection:** Apply predefined conditions to identify selected suspicious patterns.
- **Potential Port-Scan Detection:** Examine destination-port activity associated with source IP addresses.
- **High Flow-Count Detection:** Identify source IP addresses with unusually high flow counts.
- **Large Data-Transfer Detection:** Flag individual flows that exceed the implemented byte threshold.
- **Alert Explanations:** Show why traffic was flagged by a detection rule.
- **Severity Information:** Present severity classifications generated by the implemented detection logic.
- **Interactive Dashboard:** Explore traffic results and available visual summaries.
- **Filtering and Export:** Filter results and export supported records where these controls are available.
- **Sample Traffic:** Use synthetic data to demonstrate the detection workflow.

The exact output depends on the input data and the detection rules configured in the application.

## Detection Methodology

NetShield uses predefined rules rather than a machine-learning model.

### 1. Potential Port Scanning
The application examines destination-port patterns associated with source IP addresses. Activity matching the implemented port-scan rule can be flagged for investigation.

### 2. High Flow Count
The application evaluates the number of traffic flows associated with each source IP address. Sources exceeding the configured rule threshold may be flagged.

### 3. Large Byte Count
The application examines the number of bytes recorded for individual flows. Flows exceeding the implemented threshold may be flagged as potentially unusual.

### Alert Interpretation
A detected pattern is an indicator for further investigation, not proof of an attack. Legitimate services and applications may generate similar patterns.

## Installation

### Step 1: Download the project

Clone the repository:

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
```

Replace `YOUR_GITHUB_REPOSITORY_URL` with the URL of your GitHub repository.

Alternatively, download the repository as a ZIP file from GitHub and extract it.

### Step 2: Open the project folder

Open VS Code and select **File → Open Folder**. Choose the project directory containing `app.py` and `requirements.txt`.

Open the integrated terminal using **Terminal → New Terminal**.

Check the current directory:

**Windows PowerShell**
```powershell
dir
```

Make sure the required project files are visible. If they are inside a nested folder, change into that folder before continuing.

### Step 3: Create a virtual environment

**Windows**
```powershell
python -m venv .venv
```

If the `python` command is unavailable, try:

```powershell
py -m venv .venv
```

**Linux or macOS**
```bash
python3 -m venv .venv
```

### Step 4: Activate the environment

**Windows PowerShell**
```powershell
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks the activation script, you can use the following process-scoped setting in the current terminal:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Alternatively, activate the environment from Windows Command Prompt:

```bat
.venv\Scripts\activate.bat
```

**Linux or macOS**
```bash
source .venv/bin/activate
```

### Step 5: Install dependencies

From the directory containing `requirements.txt`, run:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If the command reports that `requirements.txt` cannot be found, check your current directory and navigate to the correct project folder.

## Running the Application

Once the dependencies are installed and the virtual environment is activated, execute:

```bash
streamlit run app.py
```

Streamlit will start the local application and display a URL in the terminal. Open the displayed local address in your browser, commonly:

```text
http://localhost:8501
```

Keep the terminal running while using the application.

To stop the server, press **Ctrl + C** in the terminal.

## Input CSV Format

NetShield is designed to analyze structured network-flow records. The sample dataset uses fields such as:

| Column | Description |
|---|---|
| `timestamp` | Time associated with a traffic record |
| `src_ip` | Source IP address |
| `dst_ip` | Destination IP address |
| `dst_port` | Destination port number |
| `protocol` | Network protocol |
| `bytes` | Number of bytes recorded for the flow |
| `packets` | Number of packets recorded for the flow |

A sample CSV header may look like:

```csv
timestamp,src_ip,dst_ip,dst_port,protocol,bytes,packets
```

Use the supplied sample dataset as the reference for the exact schema accepted by the current version. Input files must contain the columns required by the application's preprocessing and detection code. Additional fields may be accepted if the implementation supports them.

Suggested tests include:

- Loading a valid CSV file.
- Checking the application's response to missing or invalid columns.
- Testing a source with activity matching the implemented port-scan rule.
- Testing a source with a high flow count.
- Testing a flow with a large byte count.
- Reviewing the displayed alerts and their explanations.
- Testing the available filtering and CSV export controls.

Record actual test outcomes when preparing the project report. Synthetic testing does not establish real-world detection accuracy.

## Limitations

- Detection is based on predefined rules and thresholds.
- The system may miss attacks that do not match its implemented rules.
- Legitimate traffic may be flagged as suspicious, resulting in false positives.
- Detection quality depends on the completeness and accuracy of the input data.
- The application analyzes supplied traffic records rather than independently capturing live packets.
- An alert does not prove that a cyberattack has occurred.
- Detection performance has not been established without appropriate testing against labeled data.
